(1) ZONE DECLARATION IN RADIANT — required KVPs per zone:
- One or more brushes as classname "info_volume" with: "targetname" = <zone_name> (this string IS the zone name passed to GSC), "script_noteworthy" = "player_volume", "target" = <spawner-struct targetname, convention "<zone>_spawners">. Evidence: zone_init collects volumes via GetEntArray(zone_name,"targetname") filtered to classname=="info_volume" (STOCK/zm/_zm_zonemgr.gsc:319-330; assert no-volumes at :332). "player_volume" noteworthy is NOT read by zone_init — it is read by three OTHER systems: get_active_zones_entities (STOCK/zm/_zm_zonemgr.gsc:1232 getentarray("player_volume","script_noteworthy")), zombie_entered_playable level.playable_areas (STOCK/zm/_zm_spawner.gsc:599), and hostmigration (STOCK/zm/gametypes/_hostmigration.gsc:523). Omitting it breaks playable-area/cleanup logic, not zone init.
- Multiple info_volumes may share one targetname (all become zone.volumes, _zm_zonemgr.gsc:318-330), BUT spawner structs are gathered ONLY from zone.volumes[0].target (_zm_zonemgr.gsc:345-347) — all volumes of a zone should carry the same "target".
- Spawn-location structs: classname "script_struct", "targetname" = <value of the info_volume's target> (e.g. "start_zone_spawners"), "script_noteworthy" = space-separated token list. Tokens "spawn_location"/"riser_location"/"faller_location"/"custom_spawner_entry" go into bucket zone.a_loc_types["zombie_location"]; ANY other token (e.g. "dog_location") becomes its own bucket key (_zm_zonemgr.gsc:364-384, mirrored at create_spawner_list :1178-1197). Optional "script_string" on a riser struct: "find_flesh" (passed via notify("risen", spot.script_string) → self.find_flesh_struct_string, STOCK/zm/_zm_utility.gsc:299 + STOCK/zm/_zm_spawner.gsc:581-583) or a barricade id matching an exterior_goal.script_string to retarget the spot at a window node (_zm_zonemgr.gsc:387-403). Concrete shipped-style examples in the user's own map: MAP:1150-1158 (riser struct start_zone_spawners), MAP:1250-1255 (info_volume start_zone → start_zone_spawners), MAP:1698-1704 (market_zone), plus alley_zone:1795, corp_zone:1886, vault_zone:1997, roof_zone:2088, lab_zone:2179.

(3) ZONE "ACTIVE" SEMANTICS + WHO READS <zone>_spawners:
Three distinct per-zone booleans (zone_init :299-307): is_enabled (zone exists for gameplay; set by enable_zone), is_occupied (a player is IsTouching one of zone.volumes this scan; any_player_in_zone :189-209, spectators excluded), is_active (this scan: occupied OR connected-and-enabled-adjacent-to-an-occupied zone). is_spawning_allowed is set true alongside enable (:498).
- <zone>_spawners structs are read EXACTLY TWICE on the script side: (a) once at zone_init via struct::get_array(zone.volumes[0].target,"targetname") which stamps spot.zone_name, spot.is_enabled and sorts spots into zone.a_loc_types buckets (:345-404); (b) every ~1s by create_spawner_list (default level.create_spawner_list_func, __init__ :57) which CLEARS level.zm_loc_types and refills it ONLY from zones where (is_enabled && is_active && is_spawning_allowed) (:1153-1203, gate at :1166). So a zone "becoming active" means: on the next 1-second scan its riser/dog/etc structs enter level.zm_loc_types["zombie_location"]/["dog_location"]; consumers are _zm.gsc round_spawning (asserts non-empty, STOCK/zm/_zm.gsc:3697-3701, busy-waits at :3756) and zm_spawner::do_zombie_spawn (random pick :2906/:2956), dogs (STOCK/zm/_zm_ai_dogs.gsc:364), etc.
- enable_zone(zone_name) (:488-522) also: level notify(zone_name) (zone_wait_till_enabled waits on this, :75-81); unlocks player_respawn_point structs whose script_noteworthy == zone_name (:504-511); TriggerEnable(true)s barricade goals with script_noteworthy "<zone_name>_barriers" (:516-521) which were globally disabled at startup by deactivate_initial_barrier_goals (targetname "exterior_goal" with any script_noteworthy, :267-278).

(6) FLAG NAMING: flags are arbitrary strings; the shipped convention is "enter_<destination_area>" (zm_giant: "enter_outside_east", "enter_outside_west", "enter_wnuen_building", "enter_warehouse_second_floor" — STOCK/zm/zm_giant.gsc:262-278). Flags get SET by purchasable doors/debris: put "script_flag" KVP on the door trigger, comma-separated list supported; set on open, CLEARED on close (STOCK/zm/_zm_blockers.gsc:952-967; init :111-121). add_adjacent_zone auto-inits any flag it sees (:603-606), so no manual flag::init needed for door flags. For always-connected multi-zone-at-start setups the template idiom is a synthetic flag: level flag::init("always_on"); level flag::set("always_on"); inside zone_manager_init_func (STOCK/zm/zm_usermap.gsc:159-163 template_test_zone_init; user's copy ENTRY:197-201) then add_adjacent_zone(a,b,"always_on") per pair.

GOTCHAS:
- Declaring an info_volume in the map does NOTHING by itself: a zone only exists after zone_init, which is only reached via add_adjacent_zone / connect_zones / being in the manage_zones init_zones array. The repo's 6 new zones (market/alley/corp/vault/roof/lab) are currently unreachable because usermap_test_zone_init has zero add_adjacent_zone calls (scripts/zm/zm_abandoned_cyber_city.gsc:197-201).
- zone_init reads spawner structs ONLY from zone.volumes[0].target (_zm_zonemgr.gsc:345). If a zone uses multiple info_volumes, every volume must carry the same target KVP or the extra volumes' spawners are silently ignored.
- round_spawning hard-ASSERTs (and in ship builds silently returns, spawning nothing forever) if level.zm_loc_types["zombie_location"] is empty at round start (_zm.gsc:3697-3701) — i.e., if the active zone's spawner structs are mis-targeted or all noteworthy tokens are non-standard, the game soft-hangs with no zombies.
- spawn_zombie requires the actor spawner to have script_forcespawn set truthy; otherwise it returns undefined with only a dev-mode println (zombie_utility.gsc:1469,1538-1542) — a spawner missing SCRIPT_FORCESPAWN silently never spawns.
- manage_zones asserts every player_respawn_point struct has a script_noteworthy (_zm_zonemgr.gsc:826); in ship builds a missing one means the lock loop still runs but enable_zone's unlock comparison (:507) can crash dev / never match. Note enable_zone unlocks respawn points by script_noteworthy == zone_name — the template's respawn point uses noteworthy "start_room" (map line 1297), which never equals "start_zone"; stock ships this way, so do not 'fix' it by renaming the zone.
- flag arg of add_adjacent_zone: an ARRAY = AND of all flags; calling add_adjacent_zone twice for the same zone pair with two single flags = OR; mixing the two styles trips an assert (_zm_zonemgr.gsc:556).
- Flags on doors are CLEARED when the door is closed again (_zm_blockers.gsc:960-967), and if the level flag "door_can_close" is set, the zone connection is severed when the flag clears (_zm_zonemgr.gsc:731-734,760-768) — adjacency is not necessarily permanent.
- Zone scan cadence is ~1 second (wait(1) at _zm_zonemgr.gsc:983): after a door flag sets, spawner lists update on the NEXT scan, not instantly; scripts needing instant reaction should use level waittill(zone_name) / zone_wait_till_enabled (:75-81) or the "newzoneActive" notify (:916).
- "zones_initialized" and "begin_spawning" are FLAGS (flag::set at _zm_zonemgr.gsc:865 and _zm.gsc:4111) — consistent with the project's existing rule that bare waittill on flag names hangs if already set.
- Omitting script_noteworthy "player_volume" on a zone info_volume does not break zone_init, but it removes the volume from level.playable_areas (_zm_spawner.gsc:599) and active-zone entity queries (_zm_zonemgr.gsc:1232), silently breaking zombie playable-area/cleanup and hostmigration logic.
- A struct with script_noteworthy "dog_location" (or any non-standard token) is NOT a zombie_location — it lands in its own level.zm_loc_types[token] bucket; dog rounds need at least one dog_location in an active zone or zm_ai_dogs picks from an empty array (_zm_ai_dogs.gsc:364).
- manage_zones' failsafe silently re-activates the FIRST initial zone whenever no occupied+spawning-allowed zone is found (_zm_zonemgr.gsc:951-967) — masking zone-wiring bugs: zombies will appear to spawn 'correctly' near start while every other zone is broken.
