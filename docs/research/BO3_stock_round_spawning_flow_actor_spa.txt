=== (1) ROUND SPAWNING LOOP — WHO PICKS WHAT ===

- GATE 2: actor count (incl. corpses) < zombie_actor_limit, clears corpses while waiting (_zm.gsc:3740-3744).
- GATE 3: `level flag::wait_till("spawn_zombies")` (_zm.gsc:3753) and `while( level.zm_loc_types["zombie_location"].size <= 0 ) wait(0.1)` (_zm.gsc:3756-3759).
- HOOKS: run_custom_ai_spawn_checks() (_zm.gsc:3761, defined 3878-3943 — merges/removes special-AI spawners+locations); `level.fn_custom_round_ai_spawn` (3770-3778, return true = you handled the spawn); `level.fn_custom_zombie_spawner_selection` (3783-3786).
- SPAWNER PICK (NOT location pick): `spawner = array::random( level.zombie_spawners )` (_zm.gsc:3799/3804; the level.zombie_spawn[level.spawner_int] branch 3791-3801 only when IS_TRUE(level.use_multiple_spawns)).

- BOOKKEEPING: `level.zombie_total--` (3813), `ai thread zombie_utility::round_spawn_failsafe()` (3819), disable can_juke (3822-3825), `wait( level.zombie_vars["zombie_spawn_delay"] )` (3834), util::wait_network_frame (3838).

=== (2) actor_spawner ↔ riser structs RELATIONSHIP ===
YES — one actor spawner serves every zone. The two systems are independent:
- `level.zombie_spawners = GetEntArray( "zombie_spawner", "script_noteworthy" )` (_zm_spawner.gsc:47) — the actor spawner entity/entities, keyed ONLY by script_noteworthy "zombie_spawner", zone-agnostic.
- The zombie spawns AT the spawner entity's origin (`guy forceteleport( spawner.origin )` zombie_utility.gsc:1506), then is RELOCATED to the randomly chosen active-zone struct by move_spawn_func/do_zombie_rise (anchor moveto, _zm_spawner.gsc:2980-2998). The struct provides position/angles/rise-fx/token; the spawner entity provides the AI archetype/character models.
- spawner.count is reset to 666 after every spawn so it never depletes (zombie_utility.gsc:1511). spawner must have script_forcespawn (zombie_utility.gsc:1469; else returns undefined, 1538-1542).
- Behavior attachment: `array::thread_all(level.zombie_spawners, &spawner::add_spawn_function, &zm_spawner::zombie_spawn_init)` + failsafe (gametypes/_zm_gametype.gsc:908-909). Spawn funcs are COPIED from spawner to actor at spawn time (spawner_shared.gsc:544-547) and run via `self thread run_spawn_functions()` (557).
- Zone→spawner association only exists in the optional level.use_multiple_spawns mode via script_int on spawner+loc/zone (_zm_spawner.gsc:56-71, do_zombie_spawn 2882-2903). Not used by the template or our map.
OUR MAP (map_source/zm/zm_abandoned_cyber_city.map): TWO roster spawners, both `"script_noteworthy" "zombie_spawner"` + `"script_forcespawn" "1"`: entity 8 classname actor_spawner_zm_factory_zombie, count 9999, origin "-131.5 630.5 208" (map:1221-1237) and entity 12 classname actor_zm_nuked_basic_01, count 9999 (map:1279-1288) — round_spawning random-picks between them, so zombie visual variety comes from spawner choice. Structs: targetname "start_zone_spawners" (riser_location + dog_location, e.g. map:1150-1157, 1190-1198) targeted by info_volume start_zone (map:1252-1255); market_zone_spawners targeted by market_zone (map:1701-1704, structs 1738-1788). Plus dog spawner entity 25 (script_noteworthy "zombie_dog_spawner", map:1441-1448). Entry script sets init_zones[0]="start_zone" (scripts/zm/zm_abandoned_cyber_city.gsc:138).

=== (3) MANUAL SPAWN FROM GSC ===
Signature: `function spawn_zombie( spawner, target_name, spawn_point, round_number )` — tmp/bo3_stock_ref/scripts/shared/ai/zombie_utility.gsc:1454. Namespace `zombie_utility` (#using scripts\shared\ai\zombie_utility).
Behavior: returns undefined if spawner undefined (1456-1460); BLOCKS in `while( GetFreeActorCount() < 1 ) WAIT_SERVER_FRAME` (1462-1465); requires IS_TRUE(spawner.script_forcespawn) (1469) else dev-print + return undefined (1538-1542); spawns via `spawner SpawnFromSpawner( 0, true )` (1479); sets guy.spawn_time, guy.team = level.zombie_team, ClearEntityOwner, forceteleport(spawner.origin), Show, spawner.count=666 (1485-1511); `round_number` (4th arg) → guy._starting_round_number (1494-1497); `target_name` → guy.targetname (1513-1516) but NOTE zombie_spawn_init later overwrites self.targetname="zombie" unconditionally (_zm_spawner.gsc:207); `spawn_point` → `guy thread [[level.move_spawn_func]](spawn_point)` only if level.move_spawn_func defined (1518-1521).
Two working chosen-struct patterns:
- A: `ai = zombie_utility::spawn_zombie( spawner, undefined, my_struct );` — move_zombie_spawn_location runs immediately, sets self.spawn_pos = my_struct (_zm_utility.gsc:197) and starts the riser/teleport sequence; the later automatic do_zombie_spawn call early-outs because spawn_pos is defined (_zm_utility.gsc:192-196).
- B: `ai = zombie_utility::spawn_zombie( spawner ); ai._rise_spot = my_struct;` set IMMEDIATELY (same server frame — works because do_zombie_spawn doesn't run until frame end); do_zombie_spawn special-cases _rise_spot and calls do_zombie_rise(my_struct) directly (_zm_spawner.gsc:2874-2879).
Struct requirements: needs .origin; .script_noteworthy token decides behavior ("riser_location" plays rise anim; missing noteworthy is defaulted to "spawn_location", _zm_utility.gsc:216-219); optional .script_string is passed through the "risen" notify and "find_flesh" makes the zombie hunt immediately (_zm_spawner.gsc:554-583); optional .target = pathing goal handed to the AI (_zm_utility.gsc:200-203); optional .zone_name copied to ai.zone_name (205-209).
Required setup: spawner from level.zombie_spawners (so zombie_spawn_init spawn-func is already attached via _zm_gametype.gsc:908 — full zombie behavior for free); level.zombie_team defined; level.move_spawn_func defined (only defaulted in round_start, _zm.gsc:4118-4121 — pattern B's _rise_spot path doesn't need it... CORRECTION: do_zombie_spawn's _rise_spot branch calls do_zombie_rise directly, bypassing move_spawn_func entirely).

THE "zombie_init_done" TIMING TRAP — exact mechanism: zombie_spawn_init runs as a spawner spawn func inside run_spawn_functions, which executes per-spawner funcs only AFTER `waittillframeend` (spawner_shared.gsc:557, 581, 594-600; util::single_thread = plain thread, util_shared.gsc:915). zombie_spawn_init has no internal waits, so it runs to completion at END of the spawn frame: it overwrites .targetname (207), .maxhealth/.health from level.zombie_health (293-311), threads zombie_think (327), calls optional level.zombie_init_done FUNCTION hook (385-388 — note: same name, different thing), sets flag `self.zombie_init_done = true` (389) and fires `self notify( "zombie_init_done" )` (391). Consequences: (a) anything you set on the AI immediately after spawn_zombie returns (same frame, pre-frame-end) that zombie_spawn_init also sets — health, maxhealth, targetname, animname, meleeDamage — gets CLOBBERED at frame end; (b) `ai waittill("zombie_init_done")` works ONLY if registered in the spawn frame; after any wait the notify has already fired and the waittill hangs forever. Stock-safe pattern: poll the flag — `while ( !IS_TRUE( self.zombie_init_done ) ) wait(.05)` (_zm_ai_faller.gsc:168-171). Our repo already implements exactly this in scripts/zm/zm_abandoned_cyber_city/_acc_elites.gsc:122-133 (spawn_zombie → poll zombie.zombie_init_done with util::wait_network_frame → then promote).
Round bookkeeping for manual spawns: spawn_zombie does NOT touch level.zombie_total (only round_spawning decrements it, _zm.gsc:3813). A manual zombie counts in get_current_zombie_count (GetAITeamArray(level.zombie_team) minus .ignore_enemy_count entities, zombie_utility.gsc:2017-2038), so it (a) consumes round_spawning's 24-AI budget and (b) blocks round end until killed — unless you set ai.ignore_enemy_count = true.

=== (4) MAKING A SPAWNED ZOMBIE TOUGHER ===
HEALTH: Safe point = after self.zombie_init_done flag is true (see trap above). Set BOTH `.maxhealth` THEN `.health` (stock always sets the pair: _zm_spawner.gsc:295/304 and 309-310; spawner_shared.gsc:526 also stamps maxhealth=health early at spawn). Round-scaled base lives in level.zombie_health, recomputed at each round start by `zombie_utility::ai_calculate_health( level.round_number )` (called _zm.gsc:3703; defined zombie_utility.gsc:1906-1929: start = zombie_vars["zombie_health_start"]=150, +zombie_vars["zombie_health_increase"]=100 per round through 9, then compounding +10% (zombie_health_increase_multiplier=0.1) from round 10, with int-overflow guard 1917-1922; var defaults _zm.gsc:1209-1211). So "2x zombie" = `z.maxhealth = 2 * level.zombie_health; z.health = z.maxhealth;`. Alternative global hook: `level.zombie_init_done = &my_func` runs on EVERY zombie at end of init, before the flag/notify (_zm_spawner.gsc:385-388); or a second `spawner::add_spawn_function` added after gametype init runs after zombie_spawn_init in array order (spawner_shared.gsc:594-600, registration _zm_gametype.gsc:908).
SCALE: SetScale on an AI actor has ZERO stock zm precedent — grep of the whole mirror shows SetScale only on script_model entities and one vehicle (archetype_robot.gsc:3520 `wasp SetScale( 0.75 )` — wasp is a vehicle; others are mp killstreak/pickup models: _counteruav.gsc:270, _satellite.gsc:117, _pickup_items.gsc:169-219). Do not rely on it for actors. There is also NO SetModel/SetCharacter on zombie actors anywhere in _zm_spawner.gsc — zombie appearance is baked into the spawner's aitype/character assets at SpawnFromSpawner. Practical visual differentiation options, in stock-correctness order: (a) dedicated spawner entity with a different aitype (our map already has two: actor_spawner_zm_factory_zombie and actor_zm_nuked_basic_01 — spawn your boss from a specific one via direct entity reference instead of array::random); (b) attachments + clientfields, the mechz pattern (script flags + tag origins server-side, mechzAddAttachments mechz.gsc:1008-1034; visuals done in mechz.csc via clientfields); (c) the zm_nuked-brutus style full model swap requires shipping custom aitype/character/xmodel assets in your zone — an asset-pipeline job, not a runtime GSC call.
BOSS-DURABILITY FLAGS (stock mini-boss spawn setup, MechzServerUtils::mechzSpawnSetup mechz.gsc:946-987): `self DisableAimAssist(); self.disableAmmoDrop = true; self.no_gib = true; self.ignore_nuke = true; self.ignore_enemy_count = true; self.ignore_round_robbin_death = true; self.zombie_move_speed = "run";` (948-957). Additionally set `self.ignore_round_spawn_failsafe = true` (checked zombie_utility.gsc:1825-1828) or the failsafe thread kills any zombie that moves <24in in level.failsafe_waittime (30s default, 1830-1835, 1870) or falls below world (1857-1867).
MECHZ AS THE STOCK MINI-BOSS REFERENCE — what exists vs what a usermap lacks: scripts/shared/ai/mechz.gsc (1711 lines) + mechz.csc + mechz.gsh all exist in the mirror. `function autoexec init()` (mechz.gsc:51-74) registers behavior-tree script APIs (76-116), two archetype spawn functions keyed on ARCHETYPE_MECHZ = "mechz" (mechz.gsc:57-60; define archetype_shared/archetype_shared.gsh:17) which run via level.spawn_funcs[self.archetype] in run_spawn_functions (spawner_shared.gsc:572-579, registration spawner_shared.gsc:3172), and TEN actor clientfields at VERSION_DLC1 (mechz.gsc:62-73) that MUST have mirror registrations client-side (mechz.csc) or the game fatals with a clientfield mismatch. Asset dependencies a usermap zone does not have: xmodels c_zom_mech_body + 7 precached attachment models (precache mechz.gsc:39-45; names mechz.gsh:22-29), ~16 FX all under "dlc1/castle/..." (mechz.gsh:42-75), weapon "electroball_grenade" (mechz.gsh:91), traversal anim set "traverse@mechz" (mechz.gsc:969), 64-unit navmesh radius (mechz.gsh:16), plus the "mechz" archetype's behavior tree/ASM/xanim DATA assets (the BT_REGISTER_API/ASM_REGISTER calls only bind script handlers to asset-side node names) and an actor spawner entity whose aitype resolves to archetype "mechz". Score event hookup already global: "death_mechz" → "kill_mechz" (_zm_score.gsc:223-225). Bottom line: linking mechz.gsc/.csc is the easy 10%; the aitype/character/BT/ASM/anim/model/FX zone assets are the blocker for usermaps — which is why the practical mini-boss for this repo is the buffed-regular-zombie approach already prototyped in _acc_elites.gsc (spawn_zombie → poll zombie_init_done → 2x maxhealth/health + ability threads, _acc_elites.gsc:113-183).

GOTCHAS:
- zombie_init_done is THREE different things sharing one name: level.zombie_init_done = optional FUNCTION hook (_zm_spawner.gsc:385-388), self.zombie_init_done = boolean flag (389), and a notify (391). The notify fires at END of the spawn frame (zombie_spawn_init runs after waittillframeend, spawner_shared.gsc:581/594-600). `waittill("zombie_init_done")` after ANY wait hangs forever (notify already fired); setting .health before it completes is silently clobbered by _zm_spawner.gsc:293-311. Only timing-immune pattern: poll `while(!IS_TRUE(ai.zombie_init_done)) wait` (_zm_ai_faller.gsc:168-171; already used correctly in _acc_elites.gsc:129-132).
- spawner.script_forcespawn is mandatory — zombie_utility::spawn_zombie returns undefined with only a /# dev println #/ if missing (zombie_utility.gsc:1469, 1538-1542). Release builds fail with zero feedback.
- level.move_spawn_func is only defaulted inside round_start (_zm.gsc:4118-4121). Calling spawn_zombie with a spawn_point before the first round starts silently skips relocation (zombie_utility.gsc:1518-1521) AND the zombie never gets the "risen" notify path completed from that call; a zombie that never receives "risen" stays in PathMode("dont move") forever (_zm_spawner.gsc:319, 581-589) — frozen at the spawner perch.
- Manually spawned zombies do NOT decrement level.zombie_total (only round_spawning does, _zm.gsc:3813). Without ai.ignore_enemy_count=true the boss blocks round end and eats the 24-zombie ai_limit budget; WITH it, the round can end and a nuke/round-rob cleanup logic ignores it for counting but the boss persists into the next round — pick deliberately.
- round_spawn_failsafe kills any zombie that moves <24 inches in 30s or falls below world (zombie_utility.gsc:1830-1867). A stationary or scripted mini-boss needs self.ignore_round_spawn_failsafe = true (checked at 1825-1828). Stock nuke powerup also kills anything without self.ignore_nuke (mechz sets it, mechz.gsc:952).
- targetname passed to spawn_zombie is overwritten — zombie_spawn_init unconditionally sets self.targetname="zombie" (_zm_spawner.gsc:207). Tag custom zombies with your own field (e.g. .acc_is_elite), never targetname.
- zombie_spawn_init can resurrect saved health: if level.a_zombie_respawn_health[archetype] is non-empty (cleanup respawn ledger, _zm_spawner.gsc:297-301) the new zombie gets that stale health instead of level.zombie_health — your post-init buff math should base off level.zombie_health, not z.health.
- level.zm_loc_types["zombie_location"] is wiped and rebuilt every 1 second by the zone-manager loop (_zm_zonemgr.gsc:1156-1159, wait(1) at 1147). Runtime edits to that array are lost within a second — control placement via zone is_spawning_allowed / spot.is_enabled / level.zm_custom_spawn_location_selection (_zm_spawner.gsc:2950-2953) instead.
- SetScale on an AI actor has no stock zm precedent (mirror-wide grep: only script_models/vehicles). Assume it does not work on actors — visually bigger boss = different spawner aitype, attachments (mechz pattern), or custom character assets in the zone; not a runtime call.
- Mechz is not script-portable: linking mechz.gsc registers 10 actor clientfields at VERSION_DLC1 (mechz.gsc:62-73) which MUST be mirrored by linking mechz.csc or the game fatals with a clientfield mismatch — and even then the "mechz" archetype's behavior tree/ASM/xanims/xmodels (c_zom_mech_*)/dlc1-castle FX/electroball_grenade weapon are DLC1 zone assets a usermap lacks. spawn funcs key off spawner archetype (spawner_shared.gsc:572-579), so without a mechz-archetype aitype spawner nothing runs.
- round_spawning ASSERTMSGs (dev) / silently returns (release) if no active zone locations exist at round start (_zm.gsc:3697-3701) — a boss-round script that disables all zones' spawning_allowed can kill the whole round engine.
