GOTCHAS:
- Adjacency flags passed to zm_zonemgr::add_adjacent_zone are NEVER flag::set by this map (no script sets them; no script_flag-consuming stock door exists). The map only works because ALL 10 zones are in the init_zones array — stock manage_zones enables every array entry (is_enabled + is_spawning_allowed), and spawning is then occupancy-driven. If you copy the adjacency-flag pattern but pass only the start zone, off-zone spawning silently never activates unless your door code does `level flag::set(<flag>)`.
- init_zones[1] = "sft_lobby" has NO info_volume anywhere in the map source: dev-mode build hits assert at _zm_zonemgr.gsc:332 ('No volumes found for zone'), and zone_init would deref undefined zone.volumes[0] at :345. It shipped only because retail strips asserts. Never list a zone without a matching info_volume targetname.
- info_volume without a 'target' KVP (bsp_torrens) is legal — zone simply has zero zombie spawn locations (guard at _zm_zonemgr.gsc:345). But a zone volume whose 'target' matches no structs gives empty spawn lists with no error.
- Custom door buys read player.score directly for the affordability check (hab_airport.gsc:279) — reading is fine; deduction goes through zm_score::minus_to_player_score. Never write player.score.
- Single mystery box contract: script_struct targetname 'treasure_chest_use' script_noteworthy 'chest_1' MUST pair with a zbarrier entity script_noteworthy 'chest_1_zbarrier' at the same origin (stock does GetEnt(noteworthy+"_zbarrier","script_noteworthy")). With chests.size==1 stock sets no_fly_away=true and IGNORES level.start_chest_name — matches our CLAUDE.md note. zombie_cost lives on the struct (here 950).
- Every moving door must MoveTo its separate *_clip brushmodel in lockstep with the visual door (and optionally NotSolid() it), or collision stays behind — every door function in this map moves door + clip pairs.
- script_flag KVP on a custom-named trigger_use is dead weight: stock _zm_blockers only sets those flags inside its own door_think (trig._door_open gated, _zm_blockers.gsc:952-963), which never runs for custom-scripted doors.
- Stock spawner sizing: one actor_spawner_zm_factory_zombie with count 9999 + script_forcespawn 1 + spawnflags 19 serves the entire multi-zone map; riser structs carry script_string 'find_flesh'.
- WebFetch/GitHub note: map_source/_prefabs URLs containing spaces ('left door.map') 404 even when percent-encoded via raw.githubusercontent.com — verify download size before trusting fetched prefab content.
- Initial player spawns can be relocated at runtime by rewriting struct .origin on the 'initial_spawn_points' and 'player_respawn_point' structs (hab_airport.gsc:773-787) — no respawn-system re-registration needed.
