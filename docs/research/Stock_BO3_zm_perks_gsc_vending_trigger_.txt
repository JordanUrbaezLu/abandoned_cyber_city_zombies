=== (2) ALREADY-OWNED CASE + BEST MEGA HOOK ===
Two stacked mechanisms:
a) In-loop branch 545-557: deny sound "evt_perk_deny" + sigh VO, continue. Trigger thread stays alive.
b) THE REAL BLOCKER — check_player_has_perk(perk) (865-895), threaded on the trigger (526), endon("death") (867): every 0.1s, for players within 128 units, self SetInvisibleToPlayer(players[i], true) if player HasPerk(perk) OR has_perk_paused OR in_revive_trigger OR equipment-blocking weapon OR hacker active OR !vending_trigger_can_player_use (875-889). An invisible-to-player use trigger shows no hint and cannot be triggered by that player, so an owner never even fires the "trigger" notify — branch (a) is effectively a race-condition guard.
Available stock override pointers in _zm_perks (there is NO level.perk_purchase_override):
- level.custom_perk_validation (560-568) — called on the trigger as self [[f]](player), return false to block; runs AFTER HasPerk check so it never sees owners. Good for blocking, useless for Mega intercept.
- level.perk_bought_func (652-655) — player-called after successful drink, args (perk). Also invoked by free-perk powerup (zm/_zm_powerup_free_perk.gsc:76-78) and give_player_all_perks (zm/_zm_utility.gsc:5921-5924). Best place to SET the sticky Mega flag on (re)buy.
- level.perk_lost_func (956-958) — player-called in perk_think when perk lost, args (perk).
- register_perk_damage_override_func → level.perk_damage_override array (2020-2030) — damage-time hooks only.
- level.override_use_solo_revive (216-219), level.override_perk_targetname (1434), level.dont_unset_perk_when_machine_paused (1236), per-perk cost-as-function-pointer (386-393, 488-498), perk_machine_power_override_thread via register_perk_machine_power_override (1874-1884).
Listening on the same trigger: YES — GSC notify("trigger", player) wakes ALL waittill listeners; stock itself runs multiple independent threads on one trigger ent (vending_trigger_think 437 + electric_perks_dialog 321 + sndPerksJingles_Timer zm/_zm_audio.gsc:1579; bump triggers use the identical waittill("trigger") loop pattern, 1646-1657). So a custom for(;;) self waittill("trigger", player) thread on each zombie_vending trigger coexists safely. BUT the owner can't press use while check_player_has_perk has made it invisible. Practical Mega options, best first:
1. KILL-AND-REPLACE: notify the trigger "death"... no — instead, simply do NOT use stock threads for owners: spawn your OWN second trigger_radius_use at t_use.origin (same 40/80 dims), own targetname, own hint ("Mega upgrade [cost]"), and run inverted visibility: SetInvisibleToPlayer(p, false) only when p HasPerk(perk) && !p.mega[perk], true otherwise. Zero fights with stock loops. (Stock precedent for spawning the trigger: 1513-1523.)
2. Fight the visibility loop: your own 0.1s loop re-calling self SetInvisibleToPlayer(player, false) for mega-eligible owners — racy (both run at wait 0.1, 892) and the stock HasPerk branch (545) will still deny the press; you'd intercept via your own waittill("trigger") listener and act before/independently of the deny. Fragile; not recommended.
3. Full replacement: trigger notify("death") kills vending_trigger_think (endon "death" 439) AND check_player_has_perk (endon "death" 867) AND electric_perks_dialog (endon "death" 323), then run a patched clone of vending_trigger_think. Most invasive but fully deterministic; note quick-revive solo logic + level.quick_revive_trigger (455-456) must be preserved.
Wrapping level._custom_perks[perk].player_thread_give (set via register_perk_threads, fields .player_thread_give/.player_thread_take, 1919-1938) works for AUGMENTING effects on every give/unpause (called at 751-754 and 1287-1290) but cannot create a second purchasable interaction.

=== (4) JUG MAX HEALTH + SPEED ===
Jugg = PERK_JUGGERNOG (specialty_armorvest). Health is 100% SCRIPT-side, not engine specialty: registered player_thread_give = give_juggernaut_perk (zm/_zm_perk_juggernaut.gsc:51, 103-107) → zm_perks::perk_set_max_health_if_jugg(PERK_JUGGERNOG, true, false). perk_set_max_health_if_jugg (791-859): case PERK_JUGGERNOG: self.preMaxHealth = self.maxhealth; n = self.maxhealth + level.zombie_vars["zombie_perk_juggernaut_health"] (798-804); that var = 100 (zm/_zm_perk_juggernaut.gsc:58; an unused "zombie_perk_juggernaut_health_upgrade"=150 exists at :59). Base player health = zombie_vars["player_base_health"] = 100 (zm/_zm.gsc:1229) → 200 with jugg. case "health_reboot" (823-836): n = player_base_health + self.n_player_health_boost (if defined, 828-831) + 100 if HasPerk(PERK_JUGGERNOG) (833-836). Pers-jugg adds level.pers_jugg_upgrade_health_bonus (842-846). APPLY: self.maxhealth = n; self SetMaxHealth(n) (848-849); optional clamp self.health (851-857). take_juggernaut_perk calls perk_set_max_health_if_jugg("health_reboot", true, true) (zm/_zm_perk_juggernaut.gsc:109-113).
Ultimate Tank (+1 hit = +~100): set self.n_player_health_boost = 100 then force a recompute via perk_set_max_health_if_jugg("health_reboot", true, false) — the health_reboot case is the ONLY one that reads n_player_health_boost, and it is re-run at every revive (zm/_zm_laststand.gsc:1354, 1435) and perk loss (take_juggernaut_perk), so the bonus self-heals across downs. A bare self SetMaxHealth(self.maxhealth+100) WILL be wiped by the next health_reboot/perk_unpause recompute (1285, 848-849).
Speed: stock per-spawn baseline self SetMoveSpeedScale(1); self SetSprintDuration(4); self SetSprintCooldown(0) in zm_usermap::giveCustomCharacters (zm/zm_usermap.gsc:336-338). Player-zombie mode uses self setMoveSpeedScale(0.3) (zm/_zm.gsc:4795). MP composes multiplicatively: self setMoveSpeedScale(self.movementSpeedModifier * self getMoveSpeedScale()) (mp/gametypes/_loadout.gsc:1140) — GetMoveSpeedScale exists for read-modify-write. Stamin-Up itself has NO server-side speed script (zm/_zm_perk_staminup.gsc:42-50 registers only basic info/precache/clientfields/machine — no register_perk_threads); sprint/speed comes engine-side from the specialty_staminup perk asset. The Flash: self SetMoveSpeedScale(1.2) (or GetMoveSpeedScale()*1.2) on give; MUST re-apply after every (re)spawn because giveCustomCharacters resets it to 1, and on perk re-give.

GOTCHAS:
- The already-owned hint/deny branch at _zm_perks.gsc:545-557 is almost never reachable: check_player_has_perk (865-895) runs SetInvisibleToPlayer(player, true) every 0.1s for owners within 128 units, so a player who has the perk cannot see or fire the use trigger at all — a Mega intercept that only listens for 'trigger' on the stock trigger will silently never fire for owners. Spawn a parallel trigger (mirror Spawn('trigger_radius_use', origin+(0,0,60),0,40,80) from 1513) with inverted per-player visibility instead.
- There is NO level.perk_purchase_override. The only stock pointers are level.custom_perk_validation (runs AFTER the HasPerk check, 560-568 — never sees owners), level.perk_bought_func (652-655), level.perk_lost_func (956-958), level.perk_damage_override array (2020-2030), level.override_use_solo_revive, level.override_perk_targetname, and per-perk cost-as-function-pointer.
- give_perk (738) does NOT check HasPerk — calling it on an owner double-increments self.num_perks, re-threads player_thread_give (jugg stacks +100 maxhealth per call), and spawns a second perk_think; guard before re-giving.
- perks are lost on DOWN, not just death: perk_think (908-967) unsets on 'player_downed'; _zm_laststand.gsc notifies 'player_downed' TWICE (270 and refire at 277-287 after 1.0s when num_perks>0) — any Mega listener on that notify must be idempotent.
- Jugg health is pure script: SetPerk(specialty_armorvest) gives no HP; HP is self.maxhealth = X; self SetMaxHealth(X) in perk_set_max_health_if_jugg (848-849). A raw SetMaxHealth(+100) for Ultimate Tank is WIPED by the 'health_reboot' recompute on every revive (_zm_laststand.gsc:1354,1435) and by perk_unpause (1285). Use self.n_player_health_boost — the only field health_reboot adds (828-831) — so the bonus survives recomputes; but note the PERK_JUGGERNOG buy case (798-804) adds 100 to CURRENT maxhealth, so set n_player_health_boost before/independent of buy order is consistent only if a health_reboot ran first or maxhealth already reflects it.
- SetMoveSpeedScale is reset to 1 on EVERY (re)spawn by zm_usermap::giveCustomCharacters (zm_usermap.gsc:336); a Flash speed boost must re-apply on 'spawned_player'/perk re-give. Compose multiplicatively via GetMoveSpeedScale (pattern at mp/gametypes/_loadout.gsc:1140) to avoid clobbering other modifiers. Stamin-Up registers no server speed code — its effect is engine-side from the specialty asset, so don't look for a script value to copy.
- Money is taken BEFORE the drink completes (596); the perk is granted only if waittill returns 'weapon_change_complete' (624-627) — getting downed mid-drink loses the points with no perk (stock behavior). A Mega flow that charges on trigger-press should mirror or refund.
- self.cost is cached ONCE at trigger init (500); changing level._custom_perks[perk].cost later does nothing unless you also update trigger.cost and the hint (reset_vending_hint_string, 376-398).
- trigger notify('death') kills ALL stock threads on a vending trigger at once (vending_trigger_think endon 439, check_player_has_perk endon 867, electric_perks_dialog endon 323) — usable for full replacement, but you must re-implement the quick-revive solo logic (451-476, level.quick_revive_trigger) and the perk+'_power_on' wait.
- Setting self._retain_perks_array[perk]=true to make a perk sticky changes semantics: perk_think returns early (929-939) so the player KEEPS the perk through downs, and _zm.gsc:3352 return_retained_perks re-gives it after full respawn with bought=false — player_thread_give re-runs (jugg health re-applies) but no clientfield/presentation 'bought' path; level.perk_bought_func is NOT called on that re-give.
- perk_pause/perk_unpause (power loss) bypass perk_think entirely: player_thread_take is called with b_pause=true (1255) vs false from perk_think (947) — a Mega take-handler must branch on that first arg or it will tear down Mega state on a mere power flicker; also _zm_laststand.gsc:244-247 silently wipes player.disabled_perks on down.
