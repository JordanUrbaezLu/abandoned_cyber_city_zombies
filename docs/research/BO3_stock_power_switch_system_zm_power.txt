TOPIC: BO3 stock power-switch system (_zm_power.gsc / _zm_perks.gsc / _zm.gsc|.csc): prefab entity contract, activation sequence, multi-switch/power-zone support, and minimal-code plan for run-randomized "switch A (Corp) vs B (Vault)"

FINDINGS:
(1) ENTITY CONTRACT THE STOCK SWITCH PREFAB MUST SATISFY (derived from consuming scripts; the prefab .map itself is in Mod Tools `map_source/_prefabs/zm/`, NOT in this repo or the tmp/bo3_stock_ref scripts-only mirror — our map currently contains NO power-switch entities, grep of map_source/zm/zm_abandoned_cyber_city.map for use_elec_switch/elec_switch/power_on returned zero matches):
- TRIGGER: a usable trigger (trigger_use) with targetname `use_elec_switch`. Collected via `GetEntArray("use_elec_switch","targetname")` in `zm_power::electric_switch_init()` (_zm_power.gsc:41) and threaded per-trigger into `function electric_switch( switch_array )` (_zm_power.gsc:54). Optional trigger KVPs the stock code reads: `target` (-> handle model + fx struct, :62-83), `script_int` (power-zone id, :102-104), `script_noteworthy "allow_power_off"` (makes it a toggle instead of one-shot, :123).
- HANDLE MODEL ("master_switch" is only a LOCAL VARIABLE name in electric_switch, not a targetname): a script_model ENT whose targetname == trigger.target and `script_noteworthy "elec_switch"` (_zm_power.gsc:64-74). It is NotSolid()'d at init (:72), `rotateroll(-90, .3)` + playsound "zmb_switch_flip" on use (:97-98), waittill "rotatedone" then playsound "zmb_turn_on" (:110-112).
- FX STRUCT: a script_struct whose targetname == trigger.target and `script_noteworthy "elec_switch_fx"` (_zm_power.gsc:76-82); PlayFX of `level._effect["switch_sparks"]` at its origin (:111). zm_usermap.gsc:119 registers that effect server-side ("electric/fx_elec_sparks_directional_orange"); client equivalent zm_giant_fx.csc:77. The CLIENT also counts these structs to size the power clientfields (_zm.csc:330).
- There is NO entity named "master_switch" and no other required entities. The whole-logic override hook `level.temporary_power_switch_logic` (a func pointer) replaces &electric_switch per trigger if defined (_zm_power.gsc:43-46).

(2) ACTIVATION SEQUENCE (electric_switch, _zm_power.gsc:85-155), for a switch WITHOUT script_int:
1. Idle: SetHintString(&"ZOMBIE_ELECTRIC_SWITCH") (:89), SetVisibleToAll (:91), `self waittill("trigger", user)` (:92), then SetInvisibleToAll (:93).
2. Handle rotates -90 roll over 0.3s + "zmb_switch_flip" (:97-98).
3. power_zone = self.script_int if defined, else undefined (:101-104).
4. `level thread zm_perks::perk_unpause_all_perks( power_zone )` (:106) — re-grants perks paused by a prior power-off (perk_unpause_all_perks at _zm_perks.gsc:1314-1330 -> perk_unpause per zombie_vending trigger, _zm_perks.gsc:1263).
5. After "rotatedone": PlayFX switch_sparks at fx struct + "zmb_turn_on" (:108-113).
6. `level turn_power_on_and_open_doors( power_zone )` (:115, defined :723-764): sets level.local_doors_stay_open=true and level.power_local_doors_globally=1 (:725-726); if power_zone undefined -> `level flag::set("power_on")` + `level clientfield::set("zombie_power_on", 0)` (:728-732); if defined -> `flag::set("power_on"+power_zone)` + clientfield set to the zone int (:735-736); then notifies "power_on" on matching `zombie_door` ents with script_noteworthy electric_door/electric_buyable_door (zone-filtered by door.script_int when zoned) (:739-763).
7. `user RecordMapEvent(ZM_MAP_EVENT_POWER_ON, ...)` (:116-120; ZM_MAP_EVENT_POWER_ON==17, _zm_utility.gsh:62).
8. If script_noteworthy != "allow_power_off": `self delete(); return;` — THE TRIGGER DELETES ITSELF after one activation (:123-127). With "allow_power_off" it loops into a power-off branch: hint &"ZOMBIE_ELECTRIC_SWITCH_OFF" (:131), perk_pause_all_perks (:143), turn_power_off_and_close_doors -> flag::clear("power_on"[+zone]) + clientfield "zombie_power_off" (:766-781).
DOWNSTREAM of the "power_on" FLAG: `watch_global_power()` (_zm_power.gsc:157-171) does flag::wait_till("power_on") -> set_global_power(true) (:474-488), which sets level._power_global and powers every registered powered item (perk vending triggers registered in standard_powered_items, :180-189; PaP registers itself via zm_power::add_powered_item, _zm_pack_a_punch.gsc:135). perk_power_on (:692-698) notifies `level notify( <machine_alias>+"_on" )` + zm_perks::perk_unpause; perk_machine_think (_zm_perks.gsc:113-162) catches alias+"_on", swaps to on_model, plays fx/sound, then `level notify( perk+"_power_on" )` (:120,:146), which releases each vending_trigger_think blocked at `level waittill( perk+"_power_on" )` (_zm_perks.gsc:504-505). "power_on" is a FLAG initialized at _zm.gsc:1615 (bare waittill hangs — already encoded in docs/19 and our CheckForPower, zm_abandoned_cyber_city.gsc:170-178).

(3) MULTIPLE SWITCHES / POWER ZONES — fully supported by stock:
- electric_switch_init threads EVERY use_elec_switch trigger independently (_zm_power.gsc:41-52); multiple switches are legal. The clientfield bit width scales with switch count: GSC sizes "zombie_power_on"/"zombie_power_off" from the COUNT OF use_elec_switch TRIGGERS (`bits = GetMinBitCountForNum(trigs.size + 1)`, _zm.gsc:1654-1661); CSC sizes the same fields from the COUNT OF elec_switch_fx STRUCTS (_zm.csc:329-336). These counts must match or the clientfield registration mismatches.
- `trigger.script_int = N` makes a switch a ZONE switch: _zm.gsc:1616-1624 auto-inits a flag `"power_on"+N` for every use_elec_switch trigger with script_int; activation then sets ONLY `"power_on"+N` (never the global "power_on" flag) (_zm_power.gsc:728-737).
- Zone membership of PERK MACHINES: put `script_int N` on the `zm_perk_machine` struct; perk_machine_spawn_init copies it onto the spawned `zombie_vending` use-trigger (`t_use.script_int = s_spawn_pos.script_int`, _zm_perks.gsc:1517-1521) and onto the machine model (:1579-1582). standard_powered_items then threads `zone_controlled_perk(trigger.script_int)` on that machine's powered item (_zm_power.gsc:185-188), which flag::wait_till("power_on"+zone) / wait_till_clear to power it (:212-227). perk_pause_all_perks/perk_unpause_all_perks(power_zone) filter on `trigger.script_int == power_zone` (_zm_perks.gsc:1295-1330). Doors zone-filter on `door.script_int == power_zone` (_zm_power.gsc:749,:759,:793).
- `zm_power::add_power_zone` DOES NOT EXIST. The other system in _zm_power.gsc is radius-based "local power": `add_local_power(origin, radius)` (:374-385), `move_local_power` (:387-411), `end_local_power` (:413-423), `has_local_power(origin)` (:425-436) — a movable power bubble over level.powered_items, unrelated to script_int zones. Power-source eligibility constants: ANY_POWER 0 / LOCAL_POWER_ONLY 1 / GLOBAL_POWER_ONLY 2 (_zm_utility.gsh:7-9, duplicated zm.gsh:7-9).

(4) MINIMAL-CUSTOM-CODE PLAN for "two switches, only one active per run":
- Radiant: place TWO full stock switch sets (per (1)): two `use_elec_switch` triggers, each targeting its own handle model (script_noteworthy elec_switch) + fx struct (script_noteworthy elec_switch_fx). Give each trigger a side tag the stock code ignores on this targetname, e.g. `script_string "corp"` / `script_string "vault"` (stock reads only target/script_int/script_noteworthy on use_elec_switch triggers). Do NOT set script_int on either (zoning would route activation to "power_on"+N and starve every existing global-"power_on" consumer). Keep exactly 2 triggers and 2 elec_switch_fx structs so GSC/CSC clientfield bit counts both compute GetMinBitCountForNum(3)=2.
- GSC (replaces the TODO body at _acc_map_randomizer.gsc:297-310): after rolling the side, `trigs = GetEntArray("use_elec_switch","targetname"); foreach(trig in trigs) if(isdefined(trig.script_string) && trig.script_string == dead_side) trig Delete();`. Timing makes this near-free: `zm_power::__main__` (which spawns the electric_switch threads) is a REGISTER_SYSTEM_EX postload func (_zm_power.gsc:24,:32-37) executed by `system::run_post_systems()` inside `CodeCallback_FinalizeInitialization` — i.e. AFTER the level entry main() returns (callbacks_shared.gsc:540-543; system_shared.gsc:21-23 "postload ... during the finalization phase"). Our `acc_main::pre_init()` runs inside main() right after `zm_usermap::main()` (zm_abandoned_cyber_city.gsc:123-128), so deleting the dead trigger there means electric_switch_init never even sees it. (Current apply site at initial_blackscreen_passed, _acc_map_randomizer.gsc:280-282, also works — Delete() kills the already-spawned electric_switch thread since its `self` dies, and `while(IsDefined(self))` guards it (_zm_power.gsc:57-59,:85) — but leaves a pre-apply window; prefer pre-tick.)
- The dead side's handle model and fx struct stay in the map untouched = docs/07_replayability.md:19 "handle inert" exactly. The live side runs 100% stock: hint, animation, sparks, "power_on" flag, perk unpause, doors, RecordMapEvent. All three hint strings are already precached (zm_abandoned_cyber_city.gsc:86-88).
- Heavier alternative only if needed: set `level.temporary_power_switch_logic = &acc_func` anywhere inside entry main() (consumed at _zm_power.gsc:43-46 after main() returns) to replace per-trigger logic wholesale — required only if one trigger must multiplex power activation + the Data-Shard emergency-drop prompt.

GOTCHAS:
- script_int on a use_elec_switch trigger reroutes activation to flag "power_on"+N and NEVER sets the global "power_on" flag (_zm_power.gsc:728-737). Every existing acc consumer (CheckForPower gsc:176, _acc_boss.gsc:222-232, _acc_emergency_drop.gsc:72) waits/checks global "power_on" — with zoned switches they would all hang/no-op silently. For the A/B design, leave script_int unset on both triggers.
- The current _acc plan uses custom trigger targetnames "acc_power_corp"/"acc_power_vault" (_acc_map_randomizer.gsc:302-309, _acc_emergency_drop.gsc:38-39). Triggers with those targetnames are INVISIBLE to zm_power (it only collects targetname "use_elec_switch", _zm_power.gsc:41) — power would never turn on through the stock pipeline. Rename to use_elec_switch and tag sides via an unused KVP (e.g. script_string).
- The stock switch trigger DELETES ITSELF after one activation unless script_noteworthy == "allow_power_off" (_zm_power.gsc:123-127). _acc_emergency_drop's plan to reuse the power trigger for shard-spend drops (which require power already ON, _acc_emergency_drop.gsc:64-75) can never fire on a deleted trigger — emergency drop needs its own separate trigger, or a level.temporary_power_switch_logic replacement. Also note two threads waittill("trigger") on the same ent BOTH receive each use.
- Clientfield bit-count mismatch trap: GSC sizes "zombie_power_on"/"zombie_power_off" from the number of use_elec_switch TRIGGERS (_zm.gsc:1654-1661); CSC sizes them from the number of elec_switch_fx STRUCTS (_zm.csc:329-336). Place exactly one fx struct per trigger (2 and 2 -> both compute 2 bits) or registration mismatches at runtime. Runtime Delete() of a trigger is safe — both registrations happen during init, before entry main() code runs.
- PlayFX crash path: if a switch trigger targets a handle model (script_noteworthy "elec_switch") but has NO companion struct with script_noteworthy "elec_switch_fx", activation crashes at PlayFX(level._effect["switch_sparks"], fx_pos.origin) — fx_pos undefined (_zm_power.gsc:95-113). Ship both or neither (a bare trigger with no .target works: no rotation/fx, power still flips).
- Global (non-zoned) power-on sets clientfield "zombie_power_on" to 0 (_zm_power.gsc:731), and the CSC handler ignores zero (`if(newVal)`, _zm.csc:390-396) — so NO client-side "power_on" notify fires for a global switch. Any future .csc visuals must key off something else (zones >=1 do propagate their int).
- Timing: zm_power::__main__ (spawns the electric_switch threads) runs in CodeCallback_FinalizeInitialization, AFTER entry main() returns (callbacks_shared.gsc:540-543). Deleting the dead trigger inside main() (acc_main::pre_init) hides it from stock entirely; the current post-initial_blackscreen_passed apply (_acc_map_randomizer.gsc:280) leaves a window where the dead switch is briefly usable, and triggerenable(false) (current code, :308) leaves the stock thread alive — Delete() is the clean kill (electric_switch guards with IsDefined(self), _zm_power.gsc:57/85).
- zm_power::add_power_zone does not exist anywhere in stock — do not cite it. Zoning is purely KVP-driven (trigger/struct/door script_int + auto-inited "power_on"+N flags, _zm.gsc:1616-1624); the only programmatic API is radius-based add_local_power/move_local_power/end_local_power (_zm_power.gsc:374-423).
- perk_unpause_all_perks at switch-flip (_zm_power.gsc:106) only RE-grants perks players already bought and lost to a power-off (_zm_perks.gsc:1263-1293); machine power-on itself flows through flag "power_on" -> watch_global_power -> set_global_power -> perk_power_on -> alias_on notify -> perk_machine_think -> level notify perk+"_power_on" releasing vending_trigger_think (_zm_perks.gsc:504-505). Don't short-circuit by notifying perk+"_power_on" manually — set the flag.
- Stock quirk: turn_power_off_and_close_doors notifies doors "power_on" (not "power_off") on the off-path too (_zm_power.gsc:789-794) — electric doors do not actually re-close on power-off except under level.temporary_power_switch_logic special-casing (:797-805). Do not rely on power-off resealing doors.
